# Cybersecurity and Privacy

**Suggested time:** 1-2 class periods  
**Connects to:** password validation, input validation, dictionaries, and files

## Learning Goals

- Distinguish authentication, authorization, encryption, and hashing.
- Identify how weak input handling or unnecessary data collection creates risk.
- Describe one privacy benefit and one privacy risk of a computing system.
- Propose a proportionate safeguard for a stated threat.

## Activity

1. Match each scenario to its primary concept:

   | Scenario | Concept choices |
   |---|---|
   | A website checks whether a login attempt belongs to a known account. | Authentication, authorization, encryption, hashing |
   | A school account lets a student view grades but not edit another student's grades. | Authentication, authorization, encryption, hashing |
   | A service transforms a password into a one-way value before storing it. | Authentication, authorization, encryption, hashing |
   | A message is converted so only a recipient with a key can read it. | Authentication, authorization, encryption, hashing |

2. Pick a familiar app or school system. List three kinds of data it might
   collect and classify each as necessary, optional, or unnecessary for one
   stated feature.
3. Write a threat-and-safeguard table for the system. Include at least three
   rows, such as a reused password, an unauthorized account change, or
   accidental exposure of a downloaded file.
4. Relate one safeguard to a Python practice: validation, least privilege,
   clear errors, or careful file handling.

## Student Deliverable

Submit the completed matching activity, a data-minimization list, and a
three-row threat-and-safeguard table.

## Evidence Checklist

- Security terms are used accurately.
- The data classification is tied to a specific feature.
- Each safeguard addresses the stated threat.
- No real passwords, personal identifiers, or private school data are used.
